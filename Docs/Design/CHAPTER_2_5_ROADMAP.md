# MazeMath Chapter 2–5 개발 검토

기준: Chapter 1 모바일 즉시 플레이판의 직접 이동, 숫자 문제, 작업대 제작, 장비 게이트, 환경 퍼즐, 보스 보호막 구조를 확장한다.

## 먼저 해결할 구조 문제

현재 `Web/Instant/game.js`는 Chapter 1의 월드 좌표, 장치, 목표 순서와 보스를 한 파일에 직접 정의한다. Chapter 2–5를 같은 방식으로 복제하지 않는다.

Chapter 2 개발 전 다음 공통 구조를 만든다.

- `ChapterDefinition`: 챕터 ID, 층 수, 시작 위치, 방/장치/사다리/게이트/보스 정의
- `ObjectiveStep`: 현재 진행 상태 → 목표 문구, 목표 위치, 필요한 행동
- `PuzzleDefinition`: 숫자/저울/발판/거울/소코반/회로 등 공통 퍼즐 데이터
- `BossDefinition`: 보호막 단계와 해제 조건
- `TutorialCue`: 첫 등장 기능에서만 “무엇을 / 왜 / 어떻게”를 보여주는 짧은 안내
- 저장 데이터에 `chapter`와 챕터별 완료 기록을 추가하되 기존 Chapter 1 저장을 마이그레이션한다.

핵심 UX 원칙은 **아이가 5초 안에 다음 행동을 말할 수 있어야 한다**이다. 목표 바에는 장소만 쓰지 않고 “행동 + 대상”을 쓴다. 새로운 장비나 퍼즐은 첫 1회만 상세 안내하고 이후에는 짧게 줄인다.

## Chapter 2 — 용암 제련소

### 학습
- 2, 3, 5단의 쉬운 곱셈
- 나머지 없는 쉬운 나눗셈
- 두 조건을 동시에 보는 사고 문제
- 2~3갈래 길을 기억하고 되돌아가기

### 게임
- 환경: 돌/용암/제련 블록
- 주 장비: **파워 렌치**
- 새 퍼즐: 파이프/전력 연결, 움직이는 발판
- 기존 장비 재사용: 곡괭이 팔로 숨은 지름길
- 핵심 루프: 전원 끊김 발견 → 렌치 제작 → 발전기 2곳 수리 → 용암 다리 가동

### 보스
**용광로 골렘**
1. 곱셈 잠금
2. 파이프 연결
3. 제한된 발판 순서

완료 후 파워 렌치의 필요성이 자연스럽게 이해되어야 한다.

## Chapter 3 — 하늘 창고

### 학습
- 빈칸 수식
- 수 배열/규칙 찾기
- 3단계 작업기억
- 공간 위치 기억

### 게임
- 환경: 높은 창고, 구름, 이동 리프트
- 주 장비: **점프 부스터**
- 새 퍼즐: 소코반 Lite, 기억 경로
- 수직 미로 비중 증가
- 떨어져도 큰 페널티 없이 최근 체크포인트 복귀

### 보스
**창고 관리자 로봇**
1. 상자 위치 퍼즐
2. 기억 경로
3. 빈칸 수식

이 챕터부터 “정답만 맞히기”보다 **관찰 → 기억 → 이동 → 해결** 비중을 높인다.

## Chapter 4 — 수정 회로 연구소

### 학습
- 덧셈/뺄셈 2단계 사고
- 쉬운 곱셈/나눗셈 혼합
- 규칙 추론
- 조건 분류

### 게임
- 환경: 수정 블록, 전기 회로, 색 신호
- 주 장비: **탐험 센서 + 에너지 실드**
- 새 퍼즐: 레이저 다중 거울, 규칙 기계, 회로 스위치
- 센서로 숨은 단서 위치를 찾되 정답 자체는 보여주지 않음
- 실드는 실수 1회를 보호해 좌절을 줄임

### 보스
**수정 코어 수호자**
1. 규칙 기계
2. 다중 레이저
3. 조건에 맞는 스위치 선택

보스전 중에도 “남은 보호막 / 다음 장치”를 항상 표시한다.

---

## Chapter 5 — 별빛 코어 타워

### 학습
Chapter 1–4의 종합. 난이도는 문제 숫자를 크게 하기보다 **단계를 하나 더 생각하게 하는 방식**으로 높인다.

- 연산 + 규칙
- 작업기억 + 공간 이동
- 여러 단서 중 필요한 정보 선택
- 쉬운 곱셈/나눗셈 유지

### 게임
- 환경: 각 챕터 블록이 섞인 최종 타워
- 장비 5종을 모두 사용
- 이전 퍼즐의 짧은 변형을 조합
- 갈림길은 많아지지만 센서/지도/지름길로 길 잃음 스트레스 억제
- 매 플레이 문제와 일부 퍼즐 배치는 시드로 변경

### 최종 보스
**별빛 코어 골렘**
1. 숫자 엔진
2. 장비 선택 게이트
3. 공간 퍼즐
4. 기억 퍼즐
5. 마지막 코어 조사

각 단계가 끝날 때 다음 행동을 구체적으로 표시한다.
예: “보호막 2/5 → 오른쪽 전력 장치에서 파워 렌치를 사용하세요.”

## 난이도 곡선

| 챕터 | 연산 | 사고/기억 | 미로 | 새로운 핵심 |
|---|---|---|---|---|
| 1 | 덧셈·뺄셈 중심 | 낮음 | 입문 | 제작·기본 퍼즐 |
| 2 | 쉬운 곱셈·나눗셈 | 낮음~중간 | 중간 | 렌치·전력 |
| 3 | 빈칸·규칙 | 중간 | 수직 강화 | 점프·기억 |
| 4 | 혼합·조건 | 중간~높음 | 중간 | 센서·회로 |
| 5 | 종합 | 높음 | 높음 | 모든 시스템 결합 |

## 권장 개발 순서

1. **P2-0 공통 챕터 데이터 구조** — Chapter 1을 데이터 정의로 이관하고 기존 플레이가 동일함을 회귀 테스트.
2. **P2-1 Chapter 2 Vertical Slice** — 시작→렌치→전력 퍼즐→보스까지 한 번 완주.
3. **P2-2 Chapter 선택/진행 저장** — Chapter 1 완료 후 Chapter 2 해금.
4. **P3 Chapter 3** — 수직 미로/소코반/기억 경로.
5. **P4 Chapter 4** — 센서/실드의 실질적 효용과 회로 퍼즐.
6. **P5 Chapter 5** — 기존 시스템 조합과 최종 보스.
7. 각 챕터마다 Chromium + WebKit 모바일 완주 자동 테스트를 추가하고, 실제 아이 플레이 관찰에서 막힌 지점을 TutorialCue에 반영.

## 범위 제한

- 챕터마다 신규 장비를 계속 추가하지 않는다. 이미 있는 5종을 점차 유용하게 만든다.
- 곱셈/나눗셈 자체를 과도하게 어렵게 하지 않는다.
- 오답, 힌트 사용, 길 잃음에 재료/XP 패널티를 주지 않는다.
- “어디로 가야 하는가”보다 “무엇을 해야 하는가”를 우선 안내한다.
