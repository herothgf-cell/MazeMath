# 모바일 10장 업데이트 — 변경·검증 기록

- 버전: Block Quest 10.1
- 기준 커밋: `65ca90fefc4a046eedb3af9352ad57fe8f250a5c`
- 대상: `Web/Instant` 모바일 웹판, 기존 GitHub Pages 주소 유지.
- Unity 소스·씬·프로젝트 버전은 이번 변경 대상이 아니다.

## 구현한 변경

발전기는 단말기 그림 대신 회전축, 구리 코일, 본체, 배기구, 전선과 가동등을 가진 전용 그래픽이다. 수리 전에는 멈추고 렌치로 세 번 수리하면 회전과 가동등·증기가 켜진다. 도구를 쓰는 동안 캐릭터가 발전기를 가리지 않도록 옆에 정렬한다.

곡괭이 휘두르기와 균열, 렌치 회전과 불꽃, 부스터 분사, 실드 보호막, 센서 스캔을 월드에 표시한다. 핫바는 실제 선택이며 캐릭터 손에 선택 도구가 보인다. 상황 버튼은 캐기/수리/들기/놓기/말 걸기로 바뀐다.

골렘은 책을 들고 직접 대화로 문제를 제공한다. `말 걸기 → 골렘의 문제 받기 → 답/퍼즐 → 정답 반응` 구조다. 보스 문제 수는 일반 챕터 3개, 5장과 10장 5개다. 마지막 정답에서 저장·완료·다음 장 해금이 한 번에 처리되어 마지막 조사 위치를 다시 찾을 필요가 없다. 필드 목표를 건너뛰고 보스를 완료할 수 없다.

기존 장비 5종의 3×3 조합식과 소모 재료는 그대로 유지한다. 이미 가진 도구는 재제작 안내를 하지 않고 필요한 경우 장착을 안내한다. 미제작 필수 도구의 재료는 준비 상자에서 보장한다.

## 3~10장 점검 중 수정한 문제

- 숨겨진 회전 배열 일치로만 판정하던 배관/레이저를 실제 연결 포트 탐색과 광선 반사로 교체. 화면 경로와 판정이 동일하다.
- 맵 밖 좌표, 다른 장의 사다리·목표·보호막 수가 노출되는 하드코딩을 챕터 데이터와 공통 로직으로 통합.
- 기억 순서 다시 보기, 틀린 후 재표시, 창을 닫거나 바꿀 때 예약 취소.
- 소코반의 한 칸 되돌리기/재시작, 저장 후 진행 중 상자·플레이어·되돌리기 기록 복원.
- 이미 가진 렌치/센서를 또 만들라는 안내와 필수 재료 부족 가능성 수정.
- 무게 상자를 잘못 들었을 때 내려놓을 수 없어 막히는 경우 수정.
- 발판 눌림·성공 체크·오답 색·다음 숫자 강조·진행도 표시. 1장 첫 발판은 접근 방향에 맞는 안내 배치, 후반 발판은 시드에 따른 배치.
- 장 변경 시 부분 진행 소실과 인벤토리/XP 별칭 동기화 문제 수정.
- 보스 문제 중복 보상·조기 완료 차단. 최종 정답 이후 자동 완료.

## 저장 호환

저장 키는 `mazemath.instant.v1`를 유지하고 내부 형식을 v3로 올린다. v1/v2 저장을 읽으면 이전 원본을 `mazemath.instant.before-v3`에 백업한 뒤 변환한다. 도구·재료·XP·완료한 장을 유지하고 기존 5장 완료자는 6장이 열린다.

각 챕터의 좌표·방문 기록·퍼즐·도구 사용 횟수는 별도 보관한다. 과거 버전이 보관하지 않았던 다른 미완료 장의 상태는 복원할 원본이 없어 새 장 상태로 시작한다. 완료 기록이 있던 장은 새 필드 목표를 다시 강요하지 않는다. 들고 이동 중인 무게 상자는 저장 복원 시 원래 자리로 돌아간다. 해결한 저울과 퍼즐은 유지한다.

## 검증 방법과 결과

- 로컬 Node: **22개 테스트 통과**. 1~10장 실제 이동/충돌/사다리 경로, 5종 제작, 저장 마이그레이션, 장 전환, 보스 순서·보상, 100개 시드 연산, 50개 시드 배관/레이저, 2종 소코반 해법 등을 검사했다.
- 로컬 Chromium: 1~10장을 실제 입력/물리 루프로 이동하여 장비 제작·도구 사용·상자 운반·발판·골렘 문제·자동 완료 검사 통과. 393×852, 844×390, 320×568, 667×375 레이아웃을 검사했다. 발전기 수리 화면을 렌더링해 확인했다.
- 로컬 컨테이너의 브라우저 탐색 정책 때문에 로컬 브라우저 실행은 인라인 로딩/테스트용 저장 스텁이다. 실제 HTTP 새로고침 및 localStorage 검증은 GitHub Actions의 Chromium/WebKit 표준 모드에서 별도로 수행한다. 로컬 스텁 검사를 실기기/HTTP 검사라고 표시하지 않는다.
- `browser.test.cjs`는 테스트 모드에서 정상 입력/물리 시간을 일정하게 진행한다. 장 전체를 순간이동하거나 해결 플래그를 미리 넣어 통과시키지 않는다. 퍼즐 답은 독립 해법으로 구해 실제 버튼으로 입력한다.
- GitHub Pages는 Node와 Chromium/WebKit 검사 모두 성공한 경우에만 배포한다. 최종 원격 결과는 해당 커밋의 Actions 기록이 근거다.
- 이번 검토는 작성자 자체 검토다. 별도 리뷰어, 실제 iPhone/Android 기기 장시간 성능·배터리 검증은 수행하지 않았다.

## 재현

```bash
node --test Web/Instant/core.test.cjs
npm install --no-save --ignore-scripts playwright@1.63.0
npx playwright install --with-deps chromium webkit
node Web/Instant/browser.test.cjs
```

화면 캡처와 실패 로그는 `TestResults/instant`에 저장한다. 공개 플레이에서는 `?test=1`을 붙이지 않는다.
