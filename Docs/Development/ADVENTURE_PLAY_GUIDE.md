# MazeMath Adventure — 실행과 검증 안내

Unity **2022.3.62f2** / 개발 브랜치 **main** / Native 구현.
UI 기준: 이전 `yeonjun_block_ui_v1.html`의 돌판 패널, 녹색 강조, 하트·경험치·6칸 퀵슬롯, 모바일 조작 구성.

## 바로 실행

로컬 변경을 먼저 보관한 다음 최신 main을 받습니다.

```bash
git pull --ff-only origin main
```

Unity에서 **MazeMath > Play Adventure**를 선택합니다. 또는 다음 씬을 더블클릭하고 Play를 누릅니다.

```text
Assets/MazeMath/Scenes/Adventure.unity
```

이번 씬은 `.unity`와 `.meta`가 저장소에 포함되어 있습니다. **Setup Project를 먼저 실행할 필요가 없습니다.** 기존 `Bootstrap` / `Gameplay`는 이전 기능 데모이며 새 모험의 시작 씬이 아닙니다.

## 조작

- 방향키 / WASD: 좌우 이동, 사다리 위아래.
- Space: 점프. E: 가까운 장치 조사·사용·상자 들기·내려놓기.
- M: 방문한 방 지도. B: 장비/가방. Esc: 닫기·일시정지.
- 숫자 문제: 화면 키패드 또는 키보드 숫자·Backspace·Enter.
- 터치: 화면 아래 방향 버튼, 점프, 조사. 여러 버튼을 동시에 누를 수 있습니다.

지도나 이전/다음 방 버튼으로 순간이동하지 않습니다. 일시정지 메뉴의 체크포인트 귀환은 길을 잃었을 때의 보조 기능입니다.

## 첫 챕터 진행

1. 오른쪽으로 탐험해 1층 숫자 제어기를 조사합니다.
2. 문제를 풀고, 지나쳤던 모모의 작업대로 돌아가 **곡괭이 팔**을 제작합니다.
3. 균열벽 앞에서 조사해 길을 엽니다. 선택 장비는 첫 필수 장비 이후 제작할 수 있습니다.
4. **3kg·5kg·2kg** 상자를 직접 들고 저울에 올립니다. **8kg**이 되면 다리가 열립니다. 빈손으로 저울을 조사하면 올린 상자를 다시 꺼냅니다.
5. 오른쪽 사다리로 2층에 올라가 거울 A/B를 회전해 광선을 센서로 연결합니다.
6. 2층의 발판을 **2 → 4 → 6**으로 밟습니다. 불필요한 발판은 점프로 지나갈 수 있습니다. 해결하면 위층 사다리와 작업대 귀환 지름길이 열립니다.
7. 3층 골렘의 숫자·발판·거울 장치를 해결해 보호막을 세 개 해제합니다.
8. 골렘 앞에서 조사하면 챕터 완료입니다. 완료 후에도 보물 탐험을 계속할 수 있습니다.

보스의 바닥 충격은 미리 예고되며 점프로 피할 수 있습니다. 문제 패널을 열고 계산하는 동안에는 이동과 보스 시간이 정지합니다. 오답으로 체력·재료를 빼앗지 않습니다.

## 제작과 인챈트

작업대는 일반 제작, 3×3 조합, 인챈트의 세 화면입니다. 곡괭이 팔·렌치·점프 부스터·실드·센서의 5종 기본 장비를 지원합니다.

3×3 화면은 **설계도 확인 → 재료 선택 → 슬롯 터치 → 조합**입니다. 틀린 배치에는 재료를 소비하지 않습니다. 장비를 버리거나 영구 파괴하는 기능은 없습니다.

장비마다 인챈트 2개가 있습니다. 최초 해금은 10 XP, 이미 해금한 효과의 변경은 무료입니다. 장착 해제한 장비의 인챈트는 활성화되지 않습니다. 메아리/회로 감지/경로 탐색은 해당 월드 표식을 강조하고, 행운은 보물 재료를 더 주며, 빠른 수리는 수리 횟수를 줄입니다. 착지 보호·실드 충전·보스 예고 연장·방문 경로·목표 방향도 각각 플레이에 연결했습니다.

## 저장

새 저장 키는 `mazemath.adventure.v2`입니다. 기존 데모 저장은 변경하지 않습니다.

현재 위치, 체크포인트, 방문 방, 장비, 장착 상태, 인챈트 해금, XP, 재료, 보상 수령 기록, 보스 진행, 미완료 숫자 문제를 하나의 검증된 스냅샷으로 저장합니다. 게임 진행 시·주기적으로·일시정지/종료 시 저장하며, 기본 저장이 손상되면 이전 유효 백업을 시도합니다.

완료한 환경 장치는 열린 상태를 유지합니다. **미완료 환경 퍼즐의 상자 배치·거울 각도·발판 진행은 이어하기 시 초기 상태로 돌아갑니다.** 미완료 숫자 문제는 같은 문제로 복구됩니다. 재료가 99개를 넘으면 초과량을 대기 보상으로 보관합니다.

## 폰트와 언어

프로젝트에 적절한 한글 폰트가 지정되어 있거나 OS 한글 폰트를 사용할 수 있으면 한글 UI를 사용합니다. 사용할 수 없는 환경에서는 누락 글리프 대신 **영문 UI + LegacyRuntime**으로 전환합니다.

WebGL에서 한글을 고정하려면 배포 권한이 있는 한글 Font 에셋을 직접 프로젝트에 넣고 Adventure 씬의 `AdventureGame.koreanFont`에 연결하거나 `Resources/MazeMathKorean` 이름으로 배치합니다. 저장소에는 폰트 바이너리를 제공하지 않습니다.

## 빌드

- `MazeMath > Build > WebGL`: `Build/Web/`
- `MazeMath > Build > Android APK`: `Build/Android/MazeMath.apk`

두 경로는 **Adventure 씬만** 빌드하며 Setup Project나 기존 씬 재생성을 호출하지 않습니다. 필요한 플랫폼 Build Support 모듈이 없으면 명확한 오류를 냅니다. Android는 ARM64/IL2CPP의 로컬 테스트용 debug APK이며, 스토어용 서명 AAB 또는 업로드는 수행하지 않습니다. 임시로 변경한 빌드 설정은 finally에서 복원합니다.

WebGL 결과는 `index.html`을 파일 더블클릭하기보다 로컬 HTTP 서버로 제공합니다. 예: 빌드 후 `Build/Web`에서 `python -m http.server 8000`을 실행하고 브라우저에서 localhost:8000으로 접속합니다.

## 검증 실행

Unity 프로젝트를 닫은 상태에서 저장소 루트 PowerShell에서:

```powershell
.\Tools\verify-unity.ps1
.\Tools\verify-unity.ps1 -BuildWeb -BuildAndroid
```

Unity 설치 경로가 다르면 `-Unity "실제 Unity.exe 경로"`를 지정합니다. 로그와 XML은 `TestResults/`에 기록됩니다. 실패 결과나 출력 파일 부재를 성공으로 처리하지 않습니다.

GitHub의 `core-tests`는 순수 C# 이동·규칙·퍼즐·진행·직렬화와 C#9 소스 구문을 검사합니다. **이것은 Unity 엔진 API 전체 컴파일, Unity PlayMode 실행, 화면 배치 확인, WebGL/APK 빌드 또는 실제 기기 플레이를 대신하지 않습니다.** 이 구현 환경에는 Unity Editor가 없어 그 단계는 실행하지 못했습니다.

## 이번 버전의 범위

첫 챕터는 **직접 설계한 3층/15구역 맵**입니다. 매번 지형 전체가 무작위로 바뀌지는 않습니다. 새 탐험은 시드가 달라지고 숫자 문제·발판 배치 순서가 변합니다. 기존 절차 생성 미로 코드는 유지했습니다.

이번 모험에는 Tier 1 장비 5종과 인챈트 10종을 연결했습니다. Tier 2 업그레이드, 완전 절차 생성 월드, 추가 챕터, 상점/온라인 동기화, 스토어 출시 검증은 이번 구현 범위에 포함하지 않습니다. 기존 소코반 데모는 보존하지만 이번 월드의 필수 퍼즐은 저울·순서 발판·거울입니다.
